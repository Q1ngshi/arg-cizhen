# 借鉴 ARG 手法 · 内容增强设计文档

> 2026-08-13 定稿前版。背景：总经理指示"不要闭门造车，学习比较火的 ARG"。研究结论（经典案例 I Love Bees / The Beast / Portal2 ARG；中文圈新标杆《大学生登山失踪事件》；反面教材 TDU Solar Crown）：**日常异化 / 证据而非故事 / 低门槛 / 防掉队** 四大规律。总经理选定四个落地方向：① 源码注释彩蛋 ② 渐进式失败引导 ③ 日常异化细节 ④ 监视感强化。
>
> 总原则：**只做内容与提示层增强，不动解谜机制、不动既有存储键、不加埋点**（埋点总数 36 与 test-tracking.js 13/13 断言保持不变）；全部新内容过六红线（不跳吓/不血腥/不直白/不卖惨/不出戏/不嘲讽玩家）。

---

## ① 源码注释彩蛋（查看网页源码是 ARG 经典发现手段）

- **位置**：`index.html` 两处 HTML 注释，伪装成"开发残留/系统痕迹"，正常浏览不可见，查看源代码/开发者工具可见。
- **内容设计**（与剧情呼应、不直白给密码）：

```
<!--
  2009-03-17 23:58:12  文档上传记录：本次修改 12 字节。
  修改者：未知。复核：无。归档：CE-2009-005。
-->
```

```
<!-- 页面加载正常。若您看到此注释，请勿在公开场合提及本页面。 -->
```

- 第一条呼应卷宗 CE-2009-005（管理员门卷宗，玩家已见过编号，联想到"档案被改过"）；第二条是"注视感"（呼应值班监视氛围）。两条均不包含任何密码/答案。
- **可及性**：手机浏览器查看源码困难 → 这是氛围彩蛋，**不是关键路径线索**（不承担引导职责，只强化世界观与惊喜感）。

## ② 渐进式失败引导（"不卡壳到红温退出"层次化）

- **范围**：三扇官网门——管理员门（xf001/2009）、07 门禁（1942）、档案门（0172）。教学门 linyuan 不动（其失败提示已含引导）。
- **机制**：每扇门一个失败计数，存 `sessionStorage`（刷新不丢、关会话重置），键：
  - `cz_fail_admin`（管理员门）、`cz_fail_gate3`（07 门禁）、`cz_fail_arch01`（档案门）
- **三档文案**（示例，实施时逐字定稿）：

| 档 | 触发 | 管理员门 | 07 门禁 | 档案门 |
|---|---|---|---|---|
| 1 | 第 1 次失败 | 现有提示（口令：卷宗落款年份 4 位数字） | 现有提示（含 67 岁等要素提示） | 现有提示（备案记录/铭牌双来源） |
| 2 | 第 2 次失败 | 追加"提示：落款在卷宗末尾，注意是汉字日期。" | 追加"提示：王执事 2009 年走，终年 67 岁——动手算一算。" | 追加"提示：官网地下档案室备案记录里，柜位一栏有编号。" |
| 3 | 第 3 次失败 | 点破："落款年份：二〇〇九年 → 2009。" | 点破："2009 − 67 = 1942。" | 点破："柜位编号 0172。" |

- **口吻红线**：所有档位为"档案科同事/系统"的协助口吻，**绝无嘲讽**（第 3 档直接给答案，是"系统认为玩家需要帮助"的严肃协助，不是讽刺）。
- **防刷**：成功解锁后清除对应计数键；再次失败从 1 重新计（简单起见按"连续失败"计，不跨成功累计）。
- **埋点**：不加（失败路径不产生新日志节点，test-tracking.js 成功路径断言不受影响）。

## ③ 日常异化细节（官网加 3 处"不对劲"公文细节）

1. **页脚版权年份错乱**：官网页脚 "© 2003 慈恩镇档案管理办公室"（官网整体 2009 语境，2003 突兀）。
2. **公告编号断档**：首页公告列表插入一条 2009-005 公告缺失的痕迹（如列表项编号 2009-004 → 2009-006，中间留一条删除线占位或直接断档并加"（005 已归档，不在公开列表）"小字）——与卷宗 CE-2009-005 呼应。
3. **来访登记怪记录**：官网某档案/页面内嵌一条"来访登记：2009-03-17 23:58 王××（无登记单位，无预约）"——呼应王执事与 17 日时间线。

- 全部为静态文本，不动任何功能与机制；不重复、不抢主线（玩家可发现可不发现，发现即增强沉浸）。

## ④ 监视感强化（系统消息偶发异常）

- **位置**：`desktop.html` 系统消息（m-sys）两条"异常"消息，在特定时机触发一次：
  1. **时间戳错乱**：玩家打开 07 门禁应用时，系统发一条消息，时间戳显示为 `2009-03-17 25:61`（异常时间，正常时间戳格式外的错乱）——文案如"日志同步完成。当前时间：2009-03-17 25:61。（校准失败）"。
  2. **称呼变化**：玩家完成 07 门禁破译（calc_break）后，系统消息改用异常称呼，如"已记录口令。访客 05 权限已更新。"（玩家从未被称为"访客 05"）。
- **触发**：各触发一次（防重复），复用现有消息去重机制；不影响任何流程与埋点。
- **红线**：异常是"系统故障感"而非恐怖跳吓；无血腥/无嘲讽（"访客 05"是中性编号，暗示玩家只是众多访客之一，强化监视叙事）。

## 验收标准

1. 源码查看可见 2 条彩蛋注释，正常浏览不可见
2. 三扇门各自连续输错 3 次：文案逐级出现档 2、档 3；刷新后计数保留；正确解锁后计数清除；文案全程无嘲讽
3. 官网可见 3 处异常细节；07 门禁打开与 calc_break 后各出现 1 条异常系统消息（时间戳错乱 / 称呼变化）
4. 回归：test-tracking.js 13/13、verify-chat.js 10/10 全过
5. 六红线扫描：新文案逐条无违规
