# 社区挂靠与传播回收 · 运营指引（R4-7C / R4-回收）

> 本文档是 R4 阶段运营动作的执行手册，对应 95 分作战图 R4-7C（社区挂靠）与「回收传播数据」两项。代码层支撑已落地（见下），剩余为运营者按本指引执行。

## 一、社区挂靠（R4-7C）

目标：把 ARG 挂在玩家真实聚集的社区上，形成「玩家发现 → 玩家传播 → 新人入局」的自然扩散，同时不破坏游戏伪装（玩家应觉得是自己挖到的，而不是运营推的）。

### 1. 谜页集建档

- 在谜语/ARG 玩家聚集地建立项目档案，作为官方（伪装成玩家）的「发现帖」入口。
- 建议平台：NGA 神秘事件版 / 豆瓣谜题小组 / 贴吧 ARG 吧 / B 站专栏。
- 帖内只放：官网链接 + 一句「整理档案时发现的，地址贴在这里，有没有人一起看看」。
- 禁止：使用官方口吻自报身份、直接剧透、列出解密链。

### 2. 迷雾 Wiki / ARG 档案库建档

- 在社区 Wiki（如 ARG 维基、密室逃脱爱好者档案）建立条目：`慈恩镇档案管理办公室`。
- 条目内容建议包含：官网入口、终端入口、已知线索关键词（`林远`、`CE-2009-005`、`恩慈大典`、`03:01`）、结局数量（勿写达成条件）。
- 目的：让后来者在搜索引擎/社区检索时能找到入口，扩大漏斗顶部。

### 3. B 站实况投稿引导文案（可复用模板）

以下文案供运营者撰写实况稿/评论区引导，保持「玩家视角」：

> 「整理档案的时候发现这个网页不对劲，地址：[官网]。它不像是普通网站……目前我已经找到了好几处矛盾的地方，还在往下挖。有一起的吗？」
> 「后半段建议开声音玩。」

- 投稿时建议标注标签：`ARG`、`解谜游戏`、`都市怪谈`、`网页游戏`。
- 评论区引导只回答「怎么进」「是不是真的」，不剧透结局。

## 二、回收传播数据（代码层已落地）

零后端回收：所有传播行为写入同源 localStorage（cz_* 惯例），玩家把交接记录复制发给运营者，即可回收整条漏斗。

### 已新增埋点（R4）

| 键 | 含义 | 写入位置 |
|---|---|---|
| `cz_share_copy` | 交接记录被复制的次数 | desktop.html `copyHandover()` |
| `cz_share_foreign` | 官网检索框输入「他人交接码」成功的次数 | index.html 交接码解码分支 |
| `cz_stage_log` | 既有游玩轨迹（含 `share_copy` / `share_foreign` 事件节点） | 双端通用 |

### 回收动作

1. 向玩家索取「交接记录」原文（交接班程序 → 复制记录）。
2. 核对尾部「系统操作日志（本班）」中的事件序列，判断漏斗卡点。
3. 传播侧指标：
   - `cz_share_copy` > 0 → 玩家产生转述意愿；
   - `cz_share_foreign` > 0 → 有玩家接了上一位的交接码（跨玩家协作发生）；
   - `cz_stage_log` 中出现 `share_copy` / `share_foreign` → 同上，按时间戳还原传播链。
4. 建议回收节奏：每批玩家通关后收集 3-5 条交接记录即可看出漏斗形态。
