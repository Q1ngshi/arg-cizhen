# 玩家模拟协议（cizhen-player）

> 目的：让 AI 以普通玩家身份完整游玩《慈恩镇档案管理办公室》，产出体验报告。
> 定位：**认知路径走查器**——发现引导不足、可发现性差、操作摩擦、逻辑断点；
> 不替代真人试玩（无法模拟主观恐怖感与「烦了关页面」）。
> 执行载体：`tools/player-walkthrough.js`（Playwright 玩家代理）+ 本协议。

---

## 一、硬规则（防知识污染）

1. **游玩期间禁止读取** `index.html` / `desktop.html` 源码、`docs/` 设计文档（含解密链）、`test/` 测试脚本——不得用代码找答案。
2. **禁止直接改 localStorage / sessionStorage 解锁跳关**（清存档除外）。
3. **禁止读取控制台 / F12 / 源码注释**（这些是深度玩家的探索层，不属于第一局普通玩家路径）。
4. **卡住时先尝试游戏内引导**（系统消息 / 检索框 / 值班员 / 渐进提示三档），同一处 ≥3 次尝试仍无进展才记为「卡点」。
5. 允许的知识白名单 = **游戏内可见信息**：官网页面、桌面终端 UI、系统消息、任务卡、检索结果。
6. 诚实标注：AI 预知答案，认知路径为「模拟」，发现不了「谜题太难」，但能发现「引导是否够」。

## 二、玩家画像

- 第一次玩、被朋友/链接转发而来、没有攻略、中等耐心（每处 ≤3 次尝试）。
- 会做的自然行为：点红色/醒目条目、翻标签页、搜陌生名字/年份、回到「信息」看引导、卡住时换地方看。
- 不会做的：读源码、查攻略、F12。

## 三、游玩协议（每步记录）

每步输出：`[动作] 意图 → 操作 → 结果(可达/卡住) → 当时在想什么`

- **旅程摘要**：从开机到哪一步，花了多少步数。
- **卡点清单**：位置 / 现象 / 尝试次数 / 游戏内引导是否生效 / 严重度（高=走不下去，中=绕路，低=迟疑）。
- **体验评分**（各 1-5）：引导清晰度 · 可发现性 · 节奏 · 穿帮 · 违和。
- **对比**：与上次走查相比（用于验证改动是否减少卡点）。

## 四、执行步骤

```bash
node serve.js                # 服务器
node tools/player-walkthrough.js   # 玩家代理（Playwright，清存档后按玩家路径走查）
```

## 五、输出《游玩报告》格式

```
# 游玩报告（第 N 次走查）
日期 / 时长 / 结束节点
一、旅程摘要
二、卡点清单（分级）
三、体验评分（5 项 × 1-5）
四、与上次对比
五、建议（按 ROI）
```
